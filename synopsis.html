1. Introduction

In digital media consumption, video platforms like YouTube serve billions of daily interactions. However, native platform analytics predominantly report static, cumulative counters (such as total views and likes) without revealing the underlying temporal dynamics of content propagation. Content strategists, market analysts, and academic researchers require granular visibility into how fast content is growing, audience engagement trajectories, and why particular media items ascend the trending chart.

YouTube Trend Intelligence (TrendX) is an advanced, production-grade video analytics platform designed to continuously monitor, capture, and compute near-real-time performance metrics for trending videos. The platform operates on a strict paradigm of empirical observation: it captures unmutated temporal snapshots into PostgreSQL, evaluates historical deltas via SQL window functions (LAG()), and calculates a transparent, multi-factor Custom Trend Score without relying on opaque machine-learning speculation.

2. Problem Statement

Existing analytics solutions and public video dashboards exhibit three fundamental deficiencies:

  1. Absence of Temporal Granularity: Standard APIs expose only current absolute numbers. When a video reaches 5,000,000 views, there is no native record indicating whether those views accumulated steadily over 3 weeks or surged in the past 60 minutes.
  2. Vulnerability to Viral Outliers: Simple weighted averages fail because view metrics (hundreds of thousands) and engagement ratios (e.g., 3% to 8%) operate on vastly disparate mathematical scales, causing raw view counts to overpower all other factors.
  3. API Quota Depletion Risks: Careless polling and use of heavy search endpoints (such as search.list at 100 quota units per call) rapidly exhaust Google's 10,000 daily free allowance, causing application failures.

3. Project Objectives

  • Automated Periodic Ingestion: Ingest the top 50 popular video records across multiple countries (India, United States, United Kingdom, Canada, Australia) on a 15-minute interval at a minimal cost of 1 quota unit per country.
  • Immutable Append-Only Snapshot Storage: Maintain historical auditability in PostgreSQL by appending snapshot rows with compound unique constraints (video_id, region, captured_at) rather than overwriting current records.
  • Temporal Rate Calculation: Dynamically compute observed views gained, window elapsed time, and view velocity (views gained per hour) using the SQL LAG() window function.
  • Transparent Custom Trend Score: Implement a percentile-normalized multi-factor scoring engine using PERCENT_RANK() across View Velocity (50%), Engagement Rate (20%), Publication Recency (15%), and Absolute Reach (15%).
  • Deterministic Rule-Based Rising Detection: Identify organic viral breakouts using verified thresholds (≥10,000 view floor and ≥5,000 views/hr velocity), preventing trivial low-view anomalies from distorting the chart.
  • Interactive Visual Intelligence Dashboard: Provide high-density charts, video dossiers, embedded playback, search/filtering, and CSV export capabilities.

The system follows a decoupling between data ingestion, analytical aggregation, and presentation layers:

5. Database Schema Design

The PostgreSQL schema enforces strict referential integrity and optimizes temporal queries through targeted composite indexes:

Table Name Primary Key / Constraint Purpose & Design Decisions
channels channel_id Stores creator identity, channel name, and avatar URL. Created upon first appearance.
categories (category_id, region) Caches YouTube category taxonomies per country. Prevents repeated quota consumption.
videos video_id Stores static facts (title, duration, publish timestamp). View counts are omitted by design.
video_snapshots id (BIGSERIAL)
UNIQUE(video_id, region, captured_at)		 Append-only temporal core. Every reading records view_count, like_count, comment_count. Prevents duplicate batch insertion.
collection_runs id (BIGSERIAL) Operational audit log tracking run start/end, videos processed, quota consumed, and status.

6. Mathematical Formulation & Scoring Engine

A. Observed Velocity & Growth Derivation

Using PostgreSQL window functions, each video's latest snapshot ($S_t$) is compared against its immediate predecessor ($S_{t-1}$):

View Delta (ΔV) = GREATEST(V_latest - V_previous, 0) Elapsed Hours (Δt) = (captured_at_latest - captured_at_previous) in seconds / 3600.0 Velocity (VPH) = ΔV / Δt (Views gained per hour) Growth Percentage = ((V_latest - V_previous) / V_previous) × 100 Engagement Rate = ((Likes + Comments) / Views) × 100

B. Custom Trend Score Formulation

To eliminate scale distortion, each metric is converted into a percentile rank ($r \in [0.0, 1.0]$) across all currently charted items:

Trend Score = ROUND [ ( 0.50 × r_velocity + 0.20 × r_engagement + 0.15 × r_recency + 0.15 × r_popularity ) × 100 ]
  • View Velocity (50%): Dominant indicator reflecting immediate viral acceleration.
  • Engagement Rate (20%): Ratio of active participatory feedback (likes + comments) to passive impressions.
  • Publication Recency (15%): Hours elapsed since upload (inverted so newer videos receive higher rank).
  • Popularity Reach (15%): Absolute cumulative viewership establishing baseline reach.
